# Backend Payment Moves Specification

## Purpose

Define how `_create_payment_moves` in `pos_payment.py` generates correct IGTF journal entries under Odoo 19.

## Requirements

### Requirement: _create_payment_moves uses Odoo 19 POS session API

The system MUST adapt `_create_payment_moves` to the Odoo 19 payment move API. Calls to removed or changed helpers such as `_credit_amounts` and `_debit_amounts` MUST be replaced with the equivalent Odoo 19 mechanism.

#### Scenario: POS order with IGTF payment

- GIVEN a paid POS order with an IGTF foreign payment of 103
- WHEN `_create_payment_moves` runs
- THEN it creates account move lines without error
- AND the move balances to zero

### Requirement: IGTF split is reflected in move lines

The system MUST split the payment move into a base receivable line and an IGTF liability line.

#### Scenario: Single IGTF payment

- GIVEN a paid order with local subtotal 100 and IGTF 3
- WHEN `_create_payment_moves` runs
- THEN one move line contains 100 to the receivable account
- AND one move line contains 3 to the IGTF account
- AND the sum of debit equals the sum of credit

### Requirement: from_pos context prevents duplicate IGTF

The system MUST propagate `from_pos=True` in the context so `l10n_ve_igtf` does not add duplicate IGTF lines.

#### Scenario: Backend IGTF module installed

- GIVEN `l10n_ve_igtf` is installed
- WHEN `_create_payment_moves` creates moves with `from_pos=True`
- THEN no additional IGTF lines are generated by the backend module

### Requirement: Foreign currency amounts are preserved

The system MUST preserve foreign currency amounts on the appropriate move lines.

#### Scenario: Foreign currency payment

- GIVEN a USD payment with foreign amount 3.00 and local amount 105
- WHEN `_create_payment_moves` runs
- THEN the USD move line shows amount currency 3.00
- AND the local currency move line shows 105 in company currency
